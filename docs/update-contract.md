# Update and local package contract

The application version is 1.4.0. A release candidate contains a strict three-part version, x64 architecture, distribution (`installed` or `portable`), exact artifact name, HTTPS release/download URLs, expected byte count and SHA-256. Metadata without a supported digest or positive bounded size cannot authorize a download. Installed copies prefer `LightHostModern-<version>-Setup.msi` and accept only the exact compatibility alias `LightHostModern-Setup.msi`; portable copies use `LightHostModern-Portable.zip`. Installation registration must match the actual host executable location, not merely an unrelated installed copy.

Each download owns a unique directory below the profile temporary directory. Transfer uses a fixed 256 KiB buffer, incremental SHA-256, byte progress and cooperative cancellation with bounded network timeouts. Only a complete, flushed file with the expected size and digest can be renamed from `.partial`. Cancellation or failure removes only that operation's package files. Package inspection also verifies internal version, architecture and application identity. ZIP validation checks required executables and the release manifest without extraction; MSI validation reads its database without starting installation.

Before applying MSI, the UI asks the host to `flush-session`. A helper copied outside the installation directory validates and holds the package against modification, opens handles to the exact host/UI process instances, and acknowledges readiness. The UI then requests host shutdown, arms the helper and exits. The helper requires both processes to exit and the explicit arm signal before running Windows Installer. Cancellation, missing acknowledgement, process identity mismatch or timeout aborts application. The helper never kills either process. Installer launch errors, user cancellation, failure, success and restart-required results are recorded in the operation log. Portable downloads are offered as validated ZIP files without starting Windows Installer or stopping the host.

Release automation uses one canonical WinUI output directory, builds host/UI/scanner/helper, runs CTest, verifies payload contents and produces local MSI/ZIP plus SHA-256/size metadata. Package inspection is not an installation lifecycle test. Actual installation, upgrade, repair and removal require a disposable Windows environment.

## Rename compatibility

The versioned MSI and the unversioned alias are byte-identical. Existing 1.3.x updaters also require the previous MSI ProductName and executable filenames. For this transition, the MSI ProductName remains `Light Host Modern`, its UpgradeCode remains unchanged, and small legacy executables forward to the canonical app. The visible app, shortcuts, install folder and main executable use `LightHostModern`. These compatibility exceptions must not be removed until the supported upgrade path no longer requires them.

Package validation retains exact names, repository URLs, versions, architectures, sizes and digests. No repository rename or remote publication is part of this local change.
